## 1. 프로젝트 개요

**fresh adventure: 중소형 온라인 신선식품 판매자의 MD·마케터를 위한 신선식품(과일·채소) 마케팅 인텔리전스 — 핵심 가치: 골든타임 발견**

제품 정의는 [PTS v0.2 §1](../planning/PTS.md#1-project-identity)을 따른다. 요약하면, 외부 시장 정보를 통합해 잠재적 판매 기회 구간(골든타임)을 찾고 마케팅·프로모션 시점을 미리 정하도록 돕는 제품이다.

> **PTS 기준 (v3.5):** 승인된 PTS v0.2(`docs/planning/PTS.md`)가 제품 전략 기준선이다. 문제·타깃·가치·용어·검증 계획이 이 기획안과 다르면 PTS를 따른다. PTS 승인은 방향 결정일 뿐이며, 사용자 문제나 분석 성능을 검증한 것이 아니다(현재 검증된 사용자 문제·제품 기능은 없음). 점수 공식, 화면 개수, 시뮬레이터, 리포트 같은 기능 상세는 PTS 승인 범위 밖이고 MVP·PRD 단계에서 정한다. 이 기획안의 기능 설명(4장·8장)은 그 단계에 넘길 **초안**이다.
>
> **규칙 (v3.5, [RULES v0.6](../../RULES.md)·`CLAUDE.md` 기준):** 다른 문서가 가진 정의(골든타임은 PTS §8, 검증 계획은 PTS §14, 역할은 TEAM_ROLES)는 이 문서에서 다시 정의하지 않고 링크한다. 구체적인 공식·기준값·지표·합격 기준은 승인된 분석 명세(`docs/analytics/`의 ANALYTICS·BUSINESS_ANALYTICS·MARKETING_ANALYTICS, D-002)에서 정하며, 이 문서의 공식·기준값은 그 명세에 넘길 초안이다. 이 저장소는 공개 저장소이므로 **네이버 데이터랩에서 나온 수치(관심도 지수, 성별·연령 비중, 상관계수 등)는 싣지 않고** 결론만 적는다. 수치는 공개 저장소에 올리지 않은 팀 내부 확인 자료에 둔다.

## 2. 기획 배경

신선식품은 판매 기간이 짧고 오래 보관하기 어려우며, 반품·재판매 기회가 제한적이다. 계절에 따라 소비자 관심이 몰리고 시장 가격도 크게 바뀐다. 그래서 적절한 판매 시기를 놓치면 상품 가치 하락, 가격 인하, 미판매 재고, 폐기, 손실로 이어질 수 있다. 이것은 업계의 **구조적 위험 요인**이며, 특정 사용자에게 얼마나 자주·크게 일어나는지는 측정하지 않았다(PTS 3장).

2026년 9월 온라인쇼핑 거래액 중 농축수산물은 1조 6,738억 원으로 전년 동월 대비 9.7% 늘었고, 식품(음·식료품+농축수산물) 거래의 80.1%가 모바일에서 일어났다([국가데이터처 온라인쇼핑동향](https://m.korea.kr/archive/expDocView.do?docId=41945), [보도](https://sateconomy.co.kr/news/view/1065588973230533)). 명절 직전에는 농축수산물 온라인 거래가 크게 늘어난다. 2017년 1월\~2026년 9월 KOSIS 온라인쇼핑동향에서 설·추석 18회를 보면, 명절 직전 2주가 걸친 달의 농축수산물 거래액은 앞뒤 달 평균보다 평균 27.1% 많았고(18회 중 16회 증가), 명절과 무관한 달은 평균 -0.4%였다(팀 분석, 5-2).

아래는 타깃 사용자가 겪을 것으로 **가정한 문제(가설)**이며, 아직 검증하지 않았다. 사용자 인터뷰(B1\~B5, 6장)로 확인한다. 핵심 가설은 "시장 분석 역량이 적은 MD·마케터는 소비자 관심의 계절 변화, 시장 가격, 원가 위험을 함께 판단하기 어려워 잠재적 판매 기회 구간을 찾고 마케팅·프로모션 시점을 정하는 데 어려움을 겪는다"이다.

- 어떤 품목의 관심도가 언제 오르기 시작하는지 미리 알기 어려움
- 품목별로 주 구매 고객층(성별·연령)과 채널(모바일·PC)을 데이터로 판단하기 어려움
- 제철·명절 프로모션을 경험에 기대어 기획함
- 시장 가격이 내려 '가격 소구'가 가능한 품목을 놓침
- 원가 급등 위험을 행사 기획 때 함께 고려하지 못해 마진이 깎임
- 관심도·가격·시장 데이터가 기관별로 흩어져 있음

fresh adventure는 흩어진 공공 데이터를 하나의 화면에 모아, 판매·홍보 시점 결정을 데이터로 뒷받침한다. 가격 인하·폐기 감소나 이익 보호는 사용자가 정보를 어떻게 쓰는지에 달린 **기대 효과**이며, 외부 데이터만으로는 측정하지 않는다(PTS 9·11장).

## 4. 핵심 기능

PTS v0.2의 가치 구분에 맞춰, **핵심 가치**는 골든타임 발견·마케팅 타이밍·프로모션 타이밍(4-3)과 원가 위험 인지(4-5, 판단 보조 장치)이고, **보조 가치**는 상품 선택 지원(4-1), 고객 관심 이해(4-2, DA1 확인 조건), 수익성 평가(4-4), AI 보조 해석(4-6)이다. 이 장의 점수 공식·배점·시뮬레이터·화면 구성은 PTS 승인 범위 밖이며, MVP·PRD 단계에서 정할 **초안**이다.

### 4-1. 수요 트렌드

**의사결정:** 지금 어떤 품목에 관심이 몰리고, 온라인 식품 시장은 어느 쪽으로 커지는가?

- 품목별 검색·쇼핑 클릭 관심도 추이 (주 단위, 전년 동기 대비)
- 관심도 급증 품목 탐지, 연관 키워드 묶음 (예: 배추·절임배추·김장)
- 온라인 식품 시장 규모: 농축수산물·음식료품 월별 온라인 거래액과 모바일 비중 (KOSIS는 품목별로 나오지 않아 상위 상품군인 농축수산물로 본다)

KPI: 관심도 지수, 관심도 증가율(주·전년), 온라인 거래액 증감률, 모바일 비중

검색·쇼핑 관심도는 네이버 한 플랫폼의 상대 지수이며, 실제 수요·구매·매출·전환·시장 점유율로 자동 해석하지 않는다(RULES §5). 관심도와 거래 흐름의 관계는 상품군 단위에서만 확인한다(AV3).

### 4-2. 타깃 고객 분석

**의사결정:** 이 품목은 누구에게, 어떤 기기로 알려야 하는가?

- 쇼핑인사이트 성별·연령대·기기(PC/모바일)별 클릭 지수 비중. 상대 지수로 계산한 비중이며 고객·구매·전환 비중이 아니다. 집단 간 직접 비교가 가능한지 먼저 확인한다(DA1). 비교할 수 없으면 이 기능을 빼거나 줄인다(6장 재설계 조건)
- 품목별 핵심 고객층과 시즌에 따른 변화 (예: 김장철 배추 관심의 연령대 이동)
- 타깃·채널 제안: 광고 타깃팅 후보, 모바일 푸시 우선 여부

### 4-3. 시즌·프로모션 캘린더

**의사결정:** 어떤 품목을 언제 행사로 내야 하는가?

- 품목별 관심도 피크 시점과 상승 시작 시점 (과거 패턴 기반 예측)
- 제철·명절·기념일(특일정보)과 관심도를 겹친 월별 프로모션 캘린더
- 프로모션 후보 점수 (초안, 데이터 분포를 보고 조정. 순위·점수 공식은 MVP·PRD에서 확정)

| 평가 지표 | 배점 | 내용 |
| --- | --- | --- |
| 관심도 모멘텀 | 30 | 최근 4주 관심도 증가율 |
| 시즌 적합도 | 25 | 과거 피크 시점·제철·명절과의 거리 |

**프로모션 수익성 연결 (v3.4 추가, BA02 · P1 · 4주차)**

**의사결정:** 이 프로모션 후보는 지금 조건에서 남는가, 몇 개를 팔아야 손해를 보지 않는가?

프로모션 후보(위 점수표)와 4-4 원가·수익성 분석을 연결해, 후보별 경제성을 함께 보여 준다. 프로모션 후보 Top 5 표시에 아래 항목을 넣을지 검토한다.

| 항목 | 내용 |
| --- | --- |
| 손익분기 판매량 | 시나리오 가정에서 손해를 보지 않는 최소 판매량 |
| 예상 이익 범위 | 시나리오 기반 이익 범위 (통계적 예측 구간이 아님) |
| 시나리오 마진율 | 가정한 판매가·비용 기준 마진율 |
| 수익성 경고 | 1개당 이익이 0 이하이거나 가정값이 잘못된 경우의 경고 |
| 비용 가정 | 계산에 쓴 원재료·포장·배송·수수료·광고·폐기율·판매가 |

- 현재 제안된 대표 품목 15개마다 **대표 상품 구성 1개**를 만든다: 상품 크기·중량, 원재료 원가, 포장비, 배송비, 플랫폼 수수료, 광고비 가정, 폐기율 가정, 판매가 가정.
- 기본 판매가는 **KAMIS 소매가 중앙값**을 제안한다. 단, 상품 규격·단위·등급·관측 기간·시장 유형이 비교 가능한 값만 쓰고, 서로 맞지 않는 가격은 비교하지 않는다.
- 관측된 시장 가격과 사용자 입력·가정 비용을 화면과 결과에서 구분한다. KAMIS 중도매가는 매입가의 **대리 지표**이지 판매자의 실제 매입가가 아니고, KAMIS 소매가는 **시장 참고 가격**이지 온라인 경쟁사 판매가가 아니다.
- 1개당 공헌이익이 0 이하이면 "현재 가정에서는 양의 손익분기 판매량이 없음"으로 표시한다. 고정비·판매가·수수료 가정이 유효하지 않으면 정의된 검증 경고를 돌려준다.
- 수익성 경고는 **판단 보조 정보**이며 프로모션 후보를 자동으로 빼지 않는다. 실제 프로모션 효과, 실현 이익, 판매 결과를 주장하지 않는다.
- 데이터: ④ KAMIS, 명시적으로 기록한 비용 시나리오

**마케팅 적기 분석 (v3.1 추가)**

**의사결정:** 이 품목의 광고·기획전을 몇 주 전에 시작하고, 언제 끝내야 하는가?

관심도가 피크일 때 행사를 시작하면 이미 늦다. 관심이 오르기 시작하는 시점에 노출을 시작해야 피크 구간의 수요를 잡을 수 있다. 그래서 피크만이 아니라 "상승 시작 → 피크 → 하락"의 흐름과 그 사이 간격을 품목별로 측정한다.

**골든타임과 시점 용어:** 골든타임, 상승 시작점(Rising Point), 피크(Peak), 마케팅 타이밍, 프로모션 타이밍, 수요 리드타임, 준비 리드타임의 정의와 해석 제약은 [PTS v0.2 §8](../planning/PTS.md#8-golden-time-and-timing-terminology)을 따르며, 이 문서에서 다시 정의하지 않는다. 특히 골든타임의 경계·기준·계산 방법은 분석 단계에서 정하고(결정 사항 16), 준비 리드타임은 관심도 데이터로 구할 수 없어 사용자 검증(B2)으로 확인한다.

골든타임 분석(상승 시작점·피크·수요 리드타임과 골든타임 추론)은 김한승이 맡고, 이를 실제 준비·집행 일정으로 바꾸는 마케팅 적기 의사결정(MA03, 제안)은 지혜인이 맡는다. 아래 '권장 마케팅 시작 주'는 준비 리드타임을 사용자 입력이나 명시한 가정으로 둔 결과다.

| 분석 항목 | 내용 | 데이터 |
| --- | --- | --- |
| 상승 시작 주 | 관심도가 연평균 대비 일정 기준 이상 오르기 시작하는 첫 주 (변화점 탐지) | 검색어·쇼핑 클릭 추이 |
| 피크 주·하락 주 | 연중 최고 주와, 피크의 절반 아래로 떨어지는 주 | 검색어·쇼핑 클릭 추이 |
| 리드타임 | 피크 주 − 상승 시작 주 = 사전 마케팅에 쓸 수 있는 기간 | 위 결과 |
| 검색 → 쇼핑 시차 | 검색 관심도가 쇼핑 클릭보다 몇 주 앞서는지 (교차상관). **확인 결과(11/26, 팀 내부 확인 자료):** 2017년 8월\~2026년 10월 주 단위로 대표 품목 후보 26개(마케팅 v2 안)를 보니(쇼핑 이상 구간 제외, 추세 제거), 24개는 같은 주(시차 0)에서 상관이 가장 높아 검색이 쇼핑을 앞서지 않았다. 마케팅 안의 기준(검색이 1\~8주 앞서고 상관 0.6 이상)을 넘는 품목은 단감·마늘뿐이다. → 상승 시작 주는 쇼핑 클릭으로 구하는 것을 기본으로 하고, 검색 선행이 확인된 품목만 검색 기준으로 앞당기는 안을 검토한다(기준값은 결정 사항 14) | 검색어 + 쇼핑 클릭 |
| 타깃별 시차 | 성별·연령대별 상승 시작 주 차이 → 먼저 반응하는 타깃부터 광고 | 쇼핑인사이트 성별·연령 |
| 명절 기준 패턴 | 설·추석 D-주차별 관심도 변화 → 명절 상품 노출 시작 주 (사과·배 등 선물 품목) | 특일정보 + 관심도 |
| 적기 안정성 | 연도별 상승 시작 주의 편차 → 편차가 작으면 신뢰도 높음 (A·B·C 등급) | 2017년 이후 연도별 결과 |

**출력:** 품목별 "권장 마케팅 시작 주 / 행사 집중 주 / 종료 주"와 신뢰도 등급을 프로모션 캘린더에 표시한다. 예: "참외: 4월 2주 노출 시작 → 5월 3주\~6월 2주 집중 → 7월 1주 종료 (신뢰도 A)"

**검증:** 2017\~2023년 패턴으로 2024\~2025년 상승 시작 주를 예측하고, 실제와의 주차 오차를 잰다 (6장 백테스트와 같은 방식). 쇼핑 클릭을 쓰는 계산은 2022년 7월\~2023년 3월 이상 구간(5-2)을 빼고, 빠진 주를 결과에 표시한다.

**한계:** 실제 광고 집행·매출 성과 데이터가 없으므로, 결과는 "관심도 기준 잠재적 적기"이지 매출을 최대화하는 시점을 증명한 것은 아니다. 계절 기준 모델(작년 같은 주, 여러 해 평균 시점)보다 나아지지 않으면 설명용 시장 모니터링으로 표현을 줄인다(6장 재설계 조건, AV1).

### 4-4. 상품 원가 및 예상 수익성 분석

**의사결정:** 이 상품을 얼마에 팔아야 남고, 몇 개를 팔아야 손해를 보지 않는가?

시장 가격과 원재료 매입가에 운영 비용을 반영해 상품 1개당 원가와 예상 이익을 계산하고, 판매량에 따른 수익성 변화를 비교한다. 온라인 경쟁 가격은 합법적 수집 경로가 없어(5-6) KAMIS 소매가(대형유통·전통시장 실제 판매가)를 시장 가격 기준으로 쓴다.

| 분석 항목 | 내용 | 데이터 |
| --- | --- | --- |
| 원재료별 구매가격 | 품목별 kg당 매입가, 산지·등급·규격별 비교 | KAMIS 중도매가 (산지·등급·크기 비교는 도매시장 정산정보) |
| 상품 1개당 원재료 원가 | 상품 용량(예: 1.5kg) × kg당 매입가 | 계산 |
| 포장비·배송비 | 박스·완충재·아이스팩, 건당 배송비 | 사용자 입력 |
| 플랫폼 수수료 | 판매가 × 수수료율 | 사용자 입력 |
| 광고·홍보비 | 판매가 대비 비율 또는 월 고정 금액 | 사용자 입력 |
| 예상 폐기비 | 원재료 원가 × 폐기율 | 사용자 입력 |
| 적정 판매가격 | 목표 마진율로 계산한 판매가를 시장 가격대(KAMIS 소매가)와 비교 | 계산 + KAMIS |
| 판매량별 예상 매출·이익 | 판매량 시나리오별 매출, 총비용, 이익 | 계산 |
| 손익분기점 | 손해를 보지 않는 최소 판매량 | 계산 |

**계산식**

- 1개당 변동비 = 원재료 원가 + 포장비 + 배송비 + 폐기비 + 판매가 × (수수료율 + 광고비율)
- 1개당 이익 = 판매가 − 1개당 변동비
- 예상 이익 = 1개당 이익 × 판매량 − 고정비(월 광고비 등)
- 손익분기 판매량 = 고정비 ÷ 1개당 이익
- 적정 판매가 = (원재료 원가 + 포장비 + 배송비 + 폐기비) ÷ (1 − 수수료율 − 광고비율 − 목표 마진율)

**함께 보는 지표**

- 가격 소구 후보: 소매가가 평년보다 낮아진 품목 ("지금이 제일 쌀 때" 행사)
- 원가 낮은 조합: 산지·등급·크기별 kg당 매입가 비교 → 산지 마케팅(예: 고랭지 배추, 제주 감귤), 크기 구성(예: 사과 대과 vs 중과), 소포장·대용량 구성
- 매입가 민감도: 매입가가 10·20% 오르면 이익과 손익분기점이 어떻게 변하는지 (4-5 원가 리스크와 연결)

**데이터 범위 (v3.1 명확화):** 실데이터로 자동 반영되는 항목은 원재료 구매가격(KAMIS 중도매가)과 시장 가격대(KAMIS 소매가)뿐이다. 포장비·배송비·플랫폼 수수료·광고비·폐기율·판매량은 공공데이터가 없으므로 사용자가 입력하는 시나리오로 두고, 팀이 정한 기본값과 그 출처(플랫폼 공개 수수료표 등)를 화면에 표시한다. 도매 단위(10kg 상자 등)를 g당 가격으로 바꾸는 단위 환산표와, 시연용 샘플 상품 3\~5개의 구성표(BOM)를 1\~2단계에서 만든다. 과거 가격 변동 분포(상·하위 10%)를 적용해 예상 이익을 한 값이 아니라 범위로 보여 준다.

**출력:** 품목별 원가 구조 표, 적정 판매가와 시장 가격대 비교, 판매량–이익 그래프(손익분기점 표시). 실제 판매자 비용 데이터는 없으므로 비용 항목은 사용자가 입력하는 시나리오 방식이며, 결과는 '예상' 수익성으로 표기한다.

**도매가 가격·구성 효과 분해 (v3.4 추가, BA03 · 조건부 P1)**

**의사결정:** 이번 주 도매가가 오른 것은 같은 등급의 단가가 올라서인가, 비싼 등급의 거래 비중이 늘어서인가?

주간 거래량 가중 도매가의 변화를 두 가지로 나눈다.

- **가격 효과:** 비교 가능한 등급 안에서 단가가 바뀐 효과
- **구성 효과:** 등급별 거래량 구성이 바뀐 효과

| 구분 | 내용 |
| --- | --- |
| 데이터 | ⑤ 공영도매시장 정산정보 |
| 가중치 | 비교 가능한 kg 단위로 환산한 거래량 |
| 비교 기준 | 같은 품목·등급·단위·시장·기간 정의 |
| 명시할 것 | 등급별 가격 정의, 등급 구성 정의, 등급 정보 결측, 기간 사이 등급 등장·소멸, 품목·시장 범위, 신규·단종 등급 처리, 결측·환산 불가 단위 처리, 분해 방법, 관측된 전체 변화와 계산 효과의 일치(reconciliation) |
| 방법 원칙 | 상호작용 효과를 일관되게 다루는 분해 방법을 평가한다. 설명되지 않은 잔차를 가격·구성 효과에 몰래 넣지 않는다 |
| 해석 한계 | 분해 결과는 도매가와 기상·공급·시장 행동 사이의 인과관계를 증명하지 않는다 |

**파일럿 (12/13까지):** 배추·사과로 먼저 확인한다. 등급 정보 채움 정도, 주별로 비교 가능한 거래량, 분해 결과의 안정성, 해석 가능성, 경영 의사결정 관련성을 본다. 결과를 근거로 10장 결정 사항 6에서 채택 여부를 정하고, 데이터 범위나 비교 가능성이 부족하면 보류한다. 본 분석은 승인된 경우에만 4주차에 한다.

**파일럿 결과 (2026-11-26, `api_check/variance_pilot_report.md`)**

| 항목 | 결과 |
| --- | --- |
| 범위 | 2024년, 전국 공영도매시장 33곳 합계, 월\~일 주. 배추(일반 배추만) 1\~3월·6\~7월, 사과(모든 품종) 1\~3월·8\~9월 |
| 데이터 | 원본 약 35만 건 중 약 30만 건 사용. 등급 코드 채움 89\~94%(등급 '값 없음'은 제외), kg 환산 불가 0%. 총물량은 kg 합계이고, kg당 단가 = 총가격 ÷ 총물량 |
| 판정 | **가능**: kg 환산 불가 물량 0%(기준 10% 미만), 신규·소멸 효과 비중 20% 초과 주 1/38주(기준 20% 미만). 모든 주에서 단가 + 구성 + 신규·소멸 = 실제 변동 일치 |
| 배추 | 19주 중 단가 16주, 변동 미미 3주, 구성 0주. 거래 물량의 약 90%가 '특' 등급이라 구성 효과가 작다 |
| 사과 | 1\~3월은 단가 9주·구성 2주·변동 미미 1주, 8\~9월(저장 → 햇사과)은 구성 4주·단가 3주. 홍로·특의 물량 비중이 5% → 44%로 늘며 원가를 끌어올림 |
| 구분 기준 | 사과를 등급만으로 묶으면 8\~9월 3주의 주요 원인이 '구성'에서 '단가'로 바뀐다. **사과는 품종 × 등급**으로 묶어야 한다 |
| 방법 | 단가 효과 = 지난주 비중 × 단가 변화, 구성 효과 = 비중 변화 × 이번주 단가, 신규·소멸 효과 = 실제 변동 − 두 효과(한 주에만 거래된 구분, 따로 보고) |

v3.4 방법 원칙과 다른 점이 있어 채택 전에 정해야 한다(결정 사항 6): ① 파일럿은 상호작용(비중 변화 × 단가 변화)을 구성 효과에 넣었다. 따로 떼어 보고할지 정한다. ② 파일럿은 전국 합계로 계산했고, v3.4 비교 기준은 '같은 시장'이다. ③ 사과는 품종 × 등급으로 묶는다.

**과거 주간 마진 기회 분석 (v3.4 추가 제안, BA04 · 선택 P2)**

**의사결정:** 과거에 원재료 원가 변화만으로 시나리오 마진이 유리했던 주는 언제였는가?

- 비교 시나리오 안에서 판매가와 다른 운영 비용 가정은 고정하고, 원재료 원가만 주간 KAMIS 중도매가로 바꿔 주간 시나리오 마진을 계산한다.
- 주간 마진을 비교 가능한 과거 계절 기준값과 비교한다.
- 품목별 관측·출하 기간 안에서만 계산하고, 비출하기 가격을 0으로 채우지 않는다.
- 데이터: ④ KAMIS
- 이 분석은 **원가 변화에 따른 과거 수익성 시나리오**이며, 실제 판매자의 과거 이익이나 최적 판매 시기의 증거로 해석하지 않는다.
- **진행 조건:** 4주차까지의 경영 분석 필수 산출물(BA01·BA02, 승인 시 BA03)을 마치고 남은 여력이 있을 때만 5주차에 진행한다. 그렇지 않으면 보류하고, 최종 발표의 확장 계획에서만 언급한다. 골든타임 핵심 기능·검증·연동·배포를 늦추지 않는다.

### 4-5. 원가 리스크 인지 (핵심 가치, 판단 보조 장치)

**의사결정:** 이 품목의 원가 위험은 어느 정도이고, 행사 판단에 무엇을 참고해야 하는가?

원가 위험은 **판단 보조 장치이지 자동 제외 규칙이 아니다**(PTS 7.3). 시장 가격이나 매입 원가 위험이 높다는 이유만으로 품목이나 프로모션 기간을 자동으로 빼지 않고, 근거와 함께 사용자 판단에 맡긴다. 실제 수익성은 fresh adventure가 보지 못하는 판매자별 비용·재고·판매가·운영 조건에 달려 있다.

- 원가 지표의 평년 대비 급변 탐지 (전 품목, KAMIS 중도매가 기준)
- 기상 기반 가격 상승 위험: 여름(고랭지)배추로 먼저 검증하고 효과가 확인되면 노지 채소로 확대
- 출력: 품목별 위험 등급(낮음·보통·높음)과 근거 → 4-3 프로모션 점수의 '원가 안정성' 항목에 참고 정보로 반영(후보에서 자동으로 빼지 않음)
- 검증: 전기 가격·계절 평균 가격 같은 단순 기준 모델과 비교한다(AV2). 기준 모델보다 나아지지 않으면 원가 정보를 참고용으로만 보여 준다

### 4-6. AI 마케팅 리포트

- 주간 수요 브리핑: 급상승 품목, 다가오는 시즌, 이번 주 마케팅 시작 권장 품목(적기 분석), 가격 소구 후보

**테스트에서 확인한 주의점**

- **분석 기간:** 관심도는 2016년(쇼핑 클릭 2017년 8월)부터, 가격은 KAMIS 1996년부터, 정산정보는 2018년부터 있다. 백테스트(2019\~2024년)와 평년(최근 5년 평균) 지수를 위해 **과일·채소의 매입가와 원가 지표는 KAMIS 중도매가로 계산**하고, 정산정보는 산지·등급·크기 비교(4-4)에만 쓴다. 정산정보로 5년 평년을 만들 수 있는 것은 2023년부터다.
- 정산정보 산지명(`plor_nm`)은 대표 품목 기준 2019년 67\~98%(딸기가 가장 낮음), 2025년 99\~100% 채워져 있다. 예전 증빙 파일의 '산지명 1%'는 하루 전체가 아니라 API 첫 페이지(1,000건)만 센 값이다. 첫 페이지에는 산지명이 빈 거래가 몰려 있어(2019년 1\~9%) 하루 전체(80\~82%)나 대표 품목(76\~79%)과 크게 다르므로, 채움 비율은 하루치를 모두 받아 품목 단위로 계산한다. 표기가 섞여 있어(`충남`/`충청남도`, 뒤 공백, 현재 행정구역명 소급 적용) 산지코드(`plor_cd`) 기준으로 묶는다. 산지에 `중국` 등 수입산도 있어 국내 산지 분석에서는 뺀다.
- 정산정보의 크기코드 `100`, 등급코드 `10`, 단위코드 `10`은 '값 없음'(`.`)이다. 코드 칸은 100% 차 있지만 실제 정보는 아니므로 이 코드를 빼고 계산한다. 크기 정보는 과일(사과 94\~98%·배 97%·복숭아 89\~96%·참외 87\~90%)은 높고 채소(감자 18\~27%·양파 22\~34%·대파 31\~35%)는 낮아, 크기별 분석은 크기 정보가 많은 품목(주로 과일)에서만 쓴다.
- KAMIS는 제철에만 가격이 조사된다(예: 복숭아·참외는 11월 0건, 딸기·감귤은 8월 0건, 제철에는 정상 조회). 평년 대비 가격 지수와 가격 소구 후보는 품목별 출하 기간 안에서만 계산한다.
- KAMIS 품목명이 정산정보와 다른 경우가 있다(대파 → `파`, 마늘 → `깐마늘(국산)`, 깐마늘은 1996년 중도매가 없음). 매핑표에서 맞춘다. 마늘의 중도매가는 `깐마늘(국산)`(소매만 있음)이 아니라 `깐마늘(대서)`·`깐마늘(남도)` 품종으로 나온다(2025년 API). 원가에 쓸 품종을 정한다.
- **쇼핑인사이트 2022년 7월\~2023년 3월 이상 구간:** 같은 달끼리 비교하면 이 구간의 쇼핑 클릭이 다른 해보다 크게 높다. 대표 품목 15개 중 과일 8개 전부와 양파·감자에서 다른 해 같은 달의 수 배였고, 같은 구간의 검색량은 평소 수준이었다. 원인은 확인하지 않았지만 실제 수요 변화보다는 쇼핑인사이트 데이터 쪽 문제로 보고, 쇼핑 클릭을 쓰는 피크·상관·적기·백테스트 계산에서 이 구간을 빼거나 표시한다. 연도별 수준 차이는 앞뒤 26주 평균 대비 비율로 없앤 뒤 계산한다.
- 정산정보 등급은 코드가 아니라 표준코드의 **등급 이름**으로 묶는다. 같은 이름이 코드 두 개로 나오고(특 = `11`·`7A`, 상 = `12`·`7B`, 무등급 = `1Z`·`7Z`), 등급 '값 없음'(`10`·`70`) 행이 배추·사과 기준 6\~11%다. 정산정보 배추(중분류 `1001`) 원본의 47%는 쌈배추(`08`)라 일반 배추 분석에서 뺀다. 표준코드에 이름이 없는 소분류 코드(예: 감귤 `07`·`08`·`09`·`11`)도 있어 품목 단위로 묶는다.
- 정산정보 소분류(품종)는 품목에 따라 52\~100%만 구분되어 있고 나머지는 `기타`이거나 비어 있다. 품종 대신 거래 월과 산지로 구분하는 방법을 함께 쓴다(예: 여름배추 = 7\~9월·강원산).
- KAMIS는 2022년부터 '친환경농산물' 구분이 추가되어, 일반 상품과 분리해 집계한다.
- KAMIS 소매 조사 시장은 대형유통이 `A-유통`·`B-유통`처럼 익명으로, 전통시장은 시장명(`경동`·`부전` 등)으로 나온다. 시장 유형 매핑표를 만든다.
- KAMIS 품목코드는 부류+품목 코드로 지정하며 추측하면 틀린다(예: `600/619`는 물오징어). 대표 품목 코드는 코드 목록에서 확인한다.

### 5-5. 데이터 처리 흐름

1. **수집:** API별 수집기가 정해진 주기로 호출하고 원본 응답을 S3에 저장한다. (가격·정산·기상 매일, 데이터랩 주 1회, 온라인쇼핑·수입 월 1회)

3. **통합:** `map_product_code`로 출처별 품목을 연결하고 품목·날짜 기준으로 RDS에 적재한다.
4. **집계:** 품목·주 단위 마트(`agg_weekly_item`)를 만든다.
5. **점검:** 수집 실패·건수 급감을 로그로 남기고 재수집한다.

| 채소 | 마늘 | 초여름(햇마늘)·김장 | 김장 양념 묶음 행사, KAMIS 품목명 `깐마늘(국산)` 매핑 필요 (수산 제외로 추가) |
| 채소 | 오이 | 봄\~여름 | 여성 관심 비중이 높아 성별 차이가 가장 뚜렷함 (수산 제외로 추가) |

예비 후보: 테스트한 과일·채소 후보 16개 중 나머지(예: 고구마). 참외·배는 축산 보류로, 복숭아·포도·감자·마늘·오이는 수산 제외로 대표 품목에 넣은 것이므로 마케팅 담당이 1주차에 바꿀 수 있다.

### 5-9. 보류 데이터: 축산물 (한우·돼지고기)

축산물은 데이터 호출 테스트는 통과했지만, 아래 문제 때문에 이번 프로젝트(2027년 1월 6일 마감)에서는 보류한다. 일정에 여유가 생기거나 최종 발표 이후 확장할 때 다시 검토한다. 테스트 결과는 재개할 때 쓰도록 여기에 남긴다.

**보류 이유**

| 문제 | 내용 |
| --- | --- |
| 돼지고기 부위별 가격 없음 | ⑫의 돼지 가격은 등급별 도체 가격뿐이라, 온라인에서 주로 파는 삼겹살·목살의 원가를 계산하기 어렵다 |
| 판매 단위 차이 | 경락가는 도체·부분육의 kg당 경매가라 소비자 판매 단위(정육 500g 등)와 달라 정육 수율 가정이 필요하다 |
| 한우 등급 기준 변경 | 2019년 말 한우 등급 기준이 개편되어, 백테스트 기간(2019\~2024년)의 등급별 가격이 개편 전후로 바로 이어지지 않을 수 있다 (재개 시 공식 자료로 확인) |
| 소매가 기간이 짧음 | KAMIS 축산 소매가가 2022년부터라 평년(5년) 비교는 경락가로만 가능하다 |
| 닭·계란 가격 없음 | ⑫에는 닭·계란·오리 가격이 없다 (등급판정 확인서만 있음) |
| 국내산만 있음 | 경락가는 국내 도축분만이라 수입 소고기·돼지고기는 반영되지 않는다 |
| 별도 서버·XML | 공공데이터포털이 아닌 축산물품질평가원 서버이고 XML로만 응답하며, 데이터셋 2개를 따로 활용신청해야 해 1주차 BI 작업이 늘어난다 |

**테스트 결과 (2026년 11월 26일)**

| 항목 | 내용 |
| --- | --- |
| 데이터 | 축산물품질평가원 [축산물경락가격정보](https://www.data.go.kr/data/15057912/openapi.do)·[축산물등급판정정보](https://www.data.go.kr/data/15058822/openapi.do) |

| 쇼핑인사이트 | 축산 6개 키워드 모두 조회됨 (예: 삼겹살은 남성, 한우는 모바일 관심 비중이 높음) |
| KAMIS 축산 소매가 | 소·돼지·닭·계란. 2022년부터만 제대로 쌓여 있음 (2018\~2021년은 하루 1건 수준) |
| 기타 | 정산정보(⑤)에는 축산물이 없음 |

**재개할 때 할 일:** 데이터셋 2개 활용신청, ⑫ XML 수집기와 `fact_livestock_auction` 테이블 추가, 대표 부위(등심·삼겹살)와 KAMIS 소매 품종 매핑, 경락가→정육 수율 기본값, 대표 품목에 한우·돼지고기 추가(4-3 가격 매력도와 4-5 원가 지표는 경락가 기준), 한우 등급 기준 변경 시점 확인, 닭·계란 포함 여부 결정.

### 5-10. 원가 데이터 품질 점검 (v3.4 추가, BA01 · P0)

**목적:** 원가 관련 데이터를 수익성 계산과 경영 의사결정 지원에 쓰기 전에, 적합성과 일관성을 확인한다.

**데이터:** ④ KAMIS, ⑤ 공영도매시장 정산정보

**KAMIS 점검 항목**

- 필수 값 결측
- 0 또는 음수 가격
- kg 환산가의 불일치
- 잘못된 품목·등급 코드 (해당하는 경우)
- 지원하지 않는 단위 환산
- 중복 가능성이 있는 데이터
- 극단적인 가격 관측값
- 품목·연도마다 다른 조사 구분과 품종 (예: 마늘 중도매는 `깐마늘(대서)`·`깐마늘(남도)`뿐, 소매·중도매 없이 '친환경농산물'만 있는 품목)

**정산정보 점검 항목**

- 필수 값 결측
- 0 또는 음수 가격·거래량
- 최저가 ≤ 평균가 ≤ 최고가 위반
- 결측을 뜻하는 자리표시 코드 (예: 크기 `100`, 등급 `10`, 단위 `10`, 5-2 참고)
- 지원하지 않는 kg 환산
- 수입산 품목
- 극단적인 가격 관측값
- 잘못된 등급·단위 매핑 (같은 등급 이름의 코드가 여러 개, 5-2)
- 표준코드에 이름이 없는 소분류 코드
- 품목 범위 밖 소분류 (예: 배추 중분류의 쌈배추·우거지·절임배추, BA03 파일럿에서 배추 원본의 47%가 쌈배추)

**데이터 처리 원칙**

- 원본 레코드는 보존하고 물리적으로 지우지 않는다.
- 제외 사유, 검증 플래그, 영향받은 레코드 수를 기록한다.
- **데이터 오류**와 **분석 범위 제외**를 구분한다.
- 수입산 품목을 그 자체로 잘못된 데이터로 분류하지 않는다. 국내산 한정은 분석 범위상 필요한 경우에만 적용한다.
- 실제 시장 가격 급등은 자동으로 지우지 않는다. 유효한 극단값은 원가 리스크 분석(4-5)을 위해 보존한다.

**역할**

| 담당 | 내용 |
| --- | --- |
| 이선진 | 경영 관점 검증 규칙 정의, 원가 데이터 품질 점검 수행, 제외 레코드 검토, 결과와 분석 한계 문서화 |
| 김민지 | 원천 필드 해석 지원, 승인된 검증 규칙을 데이터 파이프라인에 구현, 재현성과 데이터 계보(lineage) 유지 |
| 김한승 | 원가 리스크 분석과 통계적 이상치 처리에 미치는 영향 검토 |

**일정:** 2주차에 샘플 상품 수익성 계산에 필요한 KAMIS 값을 먼저 검증하고, 4주차에 승인된 전 품목과 관련 정산정보로 넓힌다.

**산출물:** 원가 데이터 품질 점검 보고서, 검증 규칙 명세, 제외·경고 요약, 재현 가능한 검증 코드, 원가 데이터 준비도 평가

## 6. 분석 방법

데이터는 일 단위로 수집하고 주 단위로 분석한다. 관심도와 가격은 일별 출렁임과 결측(주말·공휴일)이 커서, 마케팅 의사결정 단위인 주로 묶는다.

| 기능 | 분석 방법 |
| --- | --- |
| 4-1 수요 트렌드 | 관심도 증가율(주·전년 대비), 급증 탐지(최근 8주 평균 대비 Z-점수), STL 분해로 계절성 제거 후 추세 판단, 온라인 거래액 전년 동월 대비 |
| 4-2 타깃 고객 | 성별·연령대·기기별 클릭 비중과 시즌별 변화, 품목 간 고객 구성 비교(군집화로 비슷한 품목 묶기) |
| 4-3 시즌·프로모션 | 품목별 연간 피크·상승 시작 주차 추정, 명절 전후 관심도·가격 변화(이벤트 분석), 프로모션 후보 다기준 점수, 마케팅 적기 분석(변화점 탐지로 상승 시작 주, 리드타임, 검색→쇼핑 교차상관 시차, 성별·연령별 상승 시차, 연도별 편차로 신뢰도) |
| 4-4 원가·수익성 분석 | 원가 구조 모델(원재료·포장·배송·수수료·광고·폐기), 목표 마진율 기반 적정 판매가, 판매량 시나리오별 손익과 손익분기점(BEP), 매입가 변동 민감도 분석, 소매가 평년 대비 지수, kg당 매입가 분포(산지·등급·크기) |
| 4-5 원가 리스크 | 원가 지표(KAMIS 중도매가)와 거래량의 평년 대비 이상 탐지, 가격 예측(전주·계절 평균 기준 모델 대비 SARIMA·Prophet·LightGBM 비교), 여름배추 기상-가격 시차 분석 |
| 4-6 AI 리포트 | LLM + SQL 기반 질의응답, 분석 결과 테이블을 근거로 인용 |
| 5-10 원가 데이터 품질 (BA01) | 규칙 기반 검증 플래그(결측·0/음수·최저≤평균≤최고·자리표시 코드·환산 불가·중복), 극단값 표시(삭제하지 않음), 제외 사유별 건수 집계 |
| 4-3·4-4 프로모션 수익성 (BA02) | 대표 상품 구성별 공헌이익·손익분기 판매량·시나리오 마진율, 가정 검증 경고, KAMIS 소매가 중앙값 기본 판매가(비교 가능한 규격만) |
| 4-4 도매가 분해 (BA03, 조건부) | 거래량 가중 주간 도매가의 가격 효과·구성 효과 분해, 상호작용 항 처리 방법 명시, 전체 변화와 효과 합의 일치 확인 |
| 4-4 과거 주간 마진 (BA04, 선택) | 원재료 원가만 주간 KAMIS 중도매가로 바꾼 시나리오 마진, 과거 계절 기준값과 비교, 출하 기간 안에서만 계산 |

예측 모델은 시계열 순서를 유지한 학습·검증·테스트 분할을 쓰고 MAE·RMSE로 평가한다.

**여름배추 기상-가격 검증 (4-5의 시제품)**

1. 여름배추 주산지인 강원의 대관령·강릉·태백 관측소 폭염일수·누적 강수량을 주 단위로 만든다. (1996년\~, 테스트 통과. 정산정보 기준 8월 가락시장 배추 물량의 52\~68%가 강원산)
2. STL로 가격(KAMIS 배추 중도매가)의 계절성을 빼고, 기상 지표를 1\~12주 밀어 가며 시차 상관을 본다.
3. 기상 변수를 넣은 예측 모델의 오차가 줄면 경보에 쓰고, 줄지 않으면 가격·거래량 이상 탐지만 쓴다.
4. 2023년 8월(고온으로 평년 대비 48% 상승) 사례에서 경보가 제때 나왔는지 확인한다. 선행연구([KREI, 최병옥 외 2020](https://repository.krei.re.kr/handle/2018.oak/24802))와 결과 방향을 비교한다.

### 분석 검증 계획

판매·프로모션 성과 데이터가 없어도, 아래 검증으로 분석 결과의 신뢰도를 숫자로 제시한다. 검증 체계와 번호는 PTS v0.2 14장(사용자 검증 B, 분석 검증 AV, 데이터 확인 DA, 제품 가치 PV)을 따른다. **모든 합격 기준(평가 품목, 지표, 기준값)은 검증 전에 정하고 합의하며, 결과는 부정적인 것까지 관찰한 그대로 보고한다.**

| 검증 | 질문 | 방법 | 성능 지표 |
| --- | --- | --- | --- |
| ① 대리지표 검증 (AV3) | 관심도가 실제 온라인 매출 흐름을 따라가는가? | 월별 신선식품(과일·채소) 관심도 지수와 KOSIS 농축수산물 온라인 거래액(실제 금액)의 상관과 시차 상관, 계절성 제거 후 비교 (거래액은 품목별로 나오지 않고 분석에서 뺀 수산물·축산물도 포함되어 추세·시차 중심으로 해석) | 상관계수, 관심도가 거래액을 앞서는 개월 수 |
| ② 백테스트 (AV1) | 그때 이 추천을 따랐다면 맞았을까? | 2019\~2024년 각 시점에서 당시 데이터만으로 프로모션 후보·피크 시점을 만들고, 이후 4주의 실제 관심도·가격과 비교 | 피크 시점 오차(주), 방향 적중률(%), 기준 모델(작년 같은 주) 대비 MAE 개선율 |
| ③ 원가 경보 정밀도 (AV2) | 위험하다고 한 품목이 실제로 올랐나? | 과거 경보 시점 이후 4\~8주 원가 지표(4-5의 분야별 지표) 변화 확인, 여름배추는 2023년 8월 사례 포함. 전기 가격·계절 평균 가격 같은 단순 기준 모델과 비교(무작위 선택만 기준으로 쓰지 않음) | 정밀도·재현율(%), 경보 선행 주수, 단순 기준 모델 대비 개선 |

**사용자·데이터·제품 가치 검증:** 사용자 검증 B1\~B5, 데이터 확인 DA1\~DA2, 제품 가치 검증 PV1의 내용과 요구 사항은 [PTS v0.2 §14](../planning/PTS.md#14-validation-requirements)를 따른다. 이 기획안 기준 현재 상태는 다음과 같다.

- DA1(성별·연령 관심의 집단 간 비교 가능성): 조회는 대표 품목 15개 모두 통과(5-2), 비교 타당성은 미확인. 결과에 따라 4-2 범위가 바뀐다
- DA2(상품군 단위 온라인쇼핑 거래액): 통계표 `101/DT_1KE10071` 확인 완료(5-2)
- B1\~B5·PV1: 사용자 인터뷰·사용자 테스트(지혜인)로 진행, 아직 시작 전. B2의 준비 리드타임은 4-3 권장 시작 주에 쓰인다

모든 검증은 시계열 순서를 지켜(미래 정보 사용 금지) 수행하고, 결과가 기준 모델보다 나아지지 않는 기능은 대시보드에서 '참고용'으로 표시한다. 검증 ②·④에서 쇼핑 클릭을 쓰는 계산은 2022년 7월\~2023년 3월 이상 구간(5-2)을 학습·평가에서 빼고, 빠진 주를 결과에 표시한다.

**경영 분석(BA) 검증 요구사항 (v3.4 추가)**

- BA01: 검증 규칙별 해당 건수와 제외 사유를 재현 가능하게 다시 계산할 수 있어야 한다. 실제 가격 급등이 제외되지 않았는지 확인한다.
- BA02: 계산식을 예시 값으로 손계산과 대조하고, 공헌이익 0 이하·잘못된 가정값 경고가 정의대로 나오는지 확인한다. 결과는 '시나리오 기반'으로 표기한다.
- BA03: 주별로 '가격 효과 + 구성 효과 (+ 상호작용)'가 관측된 전체 변화와 일치하는지 확인하고, 설명되지 않은 잔차를 따로 보고한다.
- BA04: 비출하기 값이 0으로 채워지지 않았는지, 비교 기준값이 같은 계절 구간에서 계산됐는지 확인한다.

## 8. 대시보드와 기술 스택

대시보드는 직접 만든 웹 화면(FastAPI + 프런트엔드)으로 구현해 AWS에 배포한다.

| 화면 | 주요 내용 |
| --- | --- |
| 메인 (이번 주 브리핑) | 관심도 급상승 품목, 이번 주 마케팅 시작 권장 품목, 다가오는 시즌, 프로모션 추천 Top 5(손익분기 판매량·수익성 경고 표시 검토, BA02), 원가 위험 품목 |
| 수요 트렌드 | 품목별 관심도 추이, 연관 키워드, 온라인 식품 시장 규모 |
| 타깃 고객 | 성별·연령대·기기별 비중, 시즌별 변화, 타깃 제안 |
| 시즌·프로모션 캘린더 | 월별 캘린더(제철·명절·피크), 품목별 마케팅 시작·집중·종료 주와 신뢰도(적기 분석), 프로모션 후보 점수 |
| 원가·수익성 | 품목별 원가 구조, 적정 판매가와 시장 가격대, 판매량–이익 그래프와 손익분기점, 산지·등급·크기별 kg당 매입가, 가격 소구 후보, 원가 위험, 원가 데이터 품질 상태(BA01), 도매가 가격·구성 효과(BA03, 채택 시) |
| AI 마케팅 어시스턴트 | 주간 리포트, 자연어 질의응답 |

**구현 순서 (v3.1):** 1차 발표(12/18)까지 메인·수요 트렌드·원가·수익성 3개 화면을 로컬에서 실제 데이터로 완성하고(10장 '1차 발표 시연 범위'), 타깃 고객·시즌·프로모션 캘린더·AI 마케팅 어시스턴트는 1차 발표 이후(4주차)에 추가한다. 1차 발표 때 메인 화면의 원가 위험 품목과 마케팅 시작 권장 품목은 아직 계산 전이므로 '준비 중'으로 표시한다. 화면에 들어갈 지표는 각 분석 담당(골든타임·수요·원가 리스크 김한승, 경영 분석 이선진, 마케팅 분석 지혜인)이 결과 테이블로 계산해 넘기고(1주차에 명세 확정, 12/13 최종 전달), 차트(김민지)와 페이지(지혜인)는 조회·표시만 한다. 차트에서 지표를 다시 계산하지 않는다.

**경영 분석 화면 연동 (v3.4 제안):** BA01~BA04 결과는 이선진이 결과 테이블로 완성해 넘기고, 화면 연동은 차트 김민지·페이지 지혜인이 맡는다. 모든 수익성 수치에는 '시나리오 기반'과 사용한 가정을 함께 표시하고, 관측 가격과 가정 비용을 구분해 보여 준다. 연동 범위는 MVP 정의에서 확정하며, 1차 발표(12/18) 시연 범위는 바꾸지 않는다.

아래 기술 스택은 **TECHSTACK 승인 전 후보**다. 기술 결정은 TECHSTACK(`docs/architecture/`, 김민지)에서 정하며, 승인 전에는 의존성 설치나 프레임워크 초기화를 하지 않는다(RULES §3, `CLAUDE.md`).

| 구분 | 기술 (후보) |
| --- | --- |
| 수집·전처리 | Python, Requests, Pandas, NumPy |
| 원본 저장 | Amazon S3 |
| 데이터베이스 | Amazon RDS for PostgreSQL |
| 파이프라인 | Python ETL + 스케줄러 (EC2 cron, 필요 시 EventBridge + Lambda) |
| 분석·ML | Scikit-learn, Statsmodels, Prophet, LightGBM |
| AI | LLM API, SQL 기반 질의응답 |
| 백엔드 | FastAPI (Amazon EC2, Docker) |
| 프런트엔드 | 웹 프레임워크 + 차트 라이브러리 (예: React + Plotly.js, 팀 합의로 확정), S3 + CloudFront 배포 |
| 협업 | Git, GitHub |

AWS 배포 담당은 미정이다(10장 결정 사항 8).

**AWS 흐름:** EC2 스케줄러가 API 원본을 S3에 저장 → ETL이 RDS에 적재 → 주 1회 분석 배치가 점수·예측·위험 등급 저장 → FastAPI가 화면용 API와 AI 리포트 제공 → 프런트(S3 + CloudFront)가 표시.

**비용:** 데이터는 무료이고 AWS는 사용량 과금이다. 개발은 로컬 Docker에서 하고, AWS는 최소 사양으로 시연 기간에만 켜며 AWS Budgets 예산 알림을 건다.

## 9. 차별성과 기대 효과

기존 서비스가 관심도(데이터랩)와 가격(KAMIS)을 따로 보여주는 반면, fresh adventure는 둘을 원가 위험까지 묶어 품목별 잠재적 판매 기회 구간과 마케팅·프로모션 시점을 판단할 근거를 보여 준다.

| 기존 | fresh adventure |
| --- | --- |
| 데이터랩: 키워드별 관심도 조회 | 품목·고객층·시즌을 겹친 프로모션 후보 점수 |
| KAMIS: 가격 조회 | 가격 소구 후보와 원가 위험 판단 |
| 과거 데이터 조회 | 관심도 피크·가격 예측 |
| 마케터가 직접 해석 | 근거가 달린 AI 주간 리포트 |

- **MD·마케터 (기대 효과, 미검증):** 행사 시점을 외부 데이터 근거로 정하고, 원가 급등 위험을 함께 고려할 수 있다. 시장 조사 시간이 줄어드는지는 PV1로 확인한다.
- **판매자 (기대 효과, 측정 불가):** 판매 기회 놓침·가격 인하·폐기 위험을 줄이고 이익을 지키는 데 도움을 주는 것이 목표지만, 이는 사용자가 정보를 어떻게 쓰는지에 달려 있어 외부 데이터만으로는 측정하지 않는다(PTS 9장).
- **범위 밖:** 판매자 내부 데이터 없이 검증하거나 보장할 수 없는 항목(재고 최적화, 폐기 감소, 매출·이익 최대화, 실제 프로모션 효과 등)은 [PTS v0.2 §11](../planning/PTS.md#11-scope-and-analytical-limitations)을 따른다. fresh adventure는 재고 관리나 폐기 예측 시스템이 아니다.
- **기술:** 다중 공공 API 파이프라인, DW·마트 설계, 이기종 코드 매핑, 시계열 분석·예측, AWS 기반 웹 대시보드와 AI 서비스

## 10. 한계, 리스크, 진행 순서

데이터 10종 모두 호출이 확인됐고, 데이터 한계는 6장의 분석 검증 계획으로 보완한다. 데이터랩 약관은 검토를 마쳤다(5-7). 남은 리스크는 네이버의 AI 활용 문의 답변과, 출처 3곳(데이터랩 키워드·KAMIS·정산정보)의 품목 코드 매핑 작업량이다.

**진행 순서**

1. **데이터 검증:** 10종 API 호출 통과, 약관 검토 완료, 수산물 제외(5-6)·축산물 보류(5-9) 결정. 대표 품목 확정(초안 5-8), 코드 매핑, 품목 확정 후 과거 가격(KAMIS 중도매가) 확인이 남음.
2. **MVP (1차 발표 12/18):** 화면 3개(메인·수요 트렌드·원가·수익성)를 실제 데이터로 로컬 시연. 메인은 관심도 급상승 품목과 프로모션 추천 Top 5, 수요 트렌드는 대표 품목 15개, 원가·수익성은 샘플 상품 3개, 원가 리스크는 여름배추 기상·가격 초기 검증(발표 자료)까지 한다. 대표 품목 15개 전체의 원가·수익성 분석은 1차 이후에 한다(아래 '1차 발표 이후 구현').
3. **전체 구축:** 파이프라인 자동화 → 웹 대시보드 → AI 리포트 → AWS 배포.

**1차 발표(12/18) 시연 범위**

목표는 "공공 데이터가 파이프라인을 거쳐 실제로 화면에 나오고, MD·마케터가 그 화면으로 결정을 내릴 수 있다"는 것을 보여 주는 것이다. 시연은 로컬(Docker)에서 하고, AWS 배포는 최종 발표 전에 한다.

**일정이 밀릴 때 줄일 범위 (우선순위 낮은 것부터)**

1. 관세청 수입·KOSIS 생산량 분석 → 보류
2. 예측 모델 비교(SARIMA·Prophet·LightGBM) → 기준 모델 + 1개만
3. 고객 구성 군집화 → 성별·연령 비중 비교만
4. 산지·등급·크기별 세부 비교 → 품목 단위 평년 대비 가격 지수만
5. AI 자연어 질의응답 → 주간 리포트 생성만
6. 대표 품목 15개 → 10개 (과일·채소 각 4개 이상 유지)

메인 분석(수요 트렌드, 마케팅 적기, 원가·수익성)과 검증은 줄이지 않는다.

> v3.5의 역할 분담은 `docs/planning/TEAM_ROLES.md` **v0.6(2026-11-26 승인)**을 따른다. 결정 기록부에서 아직 '제안'인 항목(R7 수집기 분담, R9 프로모션 점수 담당, R23 김민지 역할 재정렬, R24 마케팅·BI 분석)은 승인 전까지 확정이 아니다(10장 결정 사항 7·15). 상세 업무 분해·시간 추정·RACI는 `TEAM_ROLES.md`를 따른다.

**원칙**

- 4명 모두 PM을 맡는 구조는 없앤 상태를 유지한다. 업무 영역을 맡는다고 PM이 되지 않는다.
- 조장, 프로젝트 매니저(PM), 기획안 담당, 제품 기획·컨텍스트 담당, 레포 관리, 발표자는 서로 다른 역할이다. 문서 담당이라고 전략 결정 권한을 갖지는 않는다.
- 큰 전략 결정과 범위 변경은 팀 합의로 정한다. **의견이 모이지 않으면 조장(이선진)이 최종 결정한다.** 조장은 PM·발표자를 자동으로 맡지 않는다.
- **PM은 지혜인**이다. 노션 칸반보드(작업 담당·상태·진행 관리)와 주간 수행일지 작성을 맡는다. 일정·범위 변경은 팀 합의로 정한다.
- **발표자는 미정**이다. 데모와 Q&A는 해당 영역 담당자가 지원한다.
- 레포 담당은 조율·리뷰를 맡을 뿐, 혼자 모든 구현을 맡지 않는다.

- 데이터랩 호출(쇼핑인사이트 포함)은 키를 가진 김민지만 실행한다. 다른 팀원은 요청 목록을 주고 DB에 적재된 결과를 쓴다 (약관 7.2②).
- 각 분석 담당(김한승·이선진·지혜인)은 지표를 계산해 화면용 결과 테이블로 넘기고, 백엔드·차트·페이지는 조회와 표시만 한다. 차트에서 지표를 다시 계산하지 않는다.
- 각 분석 담당이 자기 분석을 구현하고 검증한다. 김한승은 마케팅·BI 분석의 입력·정의·오용 위험을 검토하지만 검증을 대신하지 않는다. 골든타임 결과(상승 시작·피크·수요 리드타임)는 김한승이 만들어 마케팅 적기(MA03)에 넘긴다.
- GitHub 브랜치·리뷰로 코드를 관리하고, 단계가 끝날 때마다 팀 회의로 다음 단계를 결정한다.

**API 키 관리 규칙** (NAVER API HUB 약관 7.2 ②·7.3 ⑤, 5-7 참고)

- 데이터랩 Client ID는 애플리케이션 1개에 1개만 발급하고, BI엔지니어(김민지) 1명이 관리한다.
- 키는 서버 환경변수로만 두고 팀원에게 공유하거나 GitHub에 올리지 않는다. 다른 팀원은 DB에 적재된 결과만 쓴다.
- 팀원별 키로 나눠 호출해 한도를 늘리지 않는다.
- 공공데이터포털·KOSIS 키도 같은 방식(서버 보관, 저장소 업로드 금지)으로 관리한다. 공공데이터포털 키 하나로 ④⑤⑥⑦⑨⑩을 모두 쓰지만, 데이터셋마다 활용신청은 따로 해야 한다.
